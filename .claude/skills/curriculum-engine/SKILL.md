## 알고리즘 순서 (PRD 8.4 mermaid 플로우차트 그대로 따를 것)

1. 미이수 **전공필수** 과목을 선수과목 순서(위상정렬) 고려해 학기별 우선 배치
2. **전공선택 잔여 학점** 계산
3. 잔여 슬롯(전공선택→자유선택/교양 순)을 관심분야 연관도 높은 과목으로 채움 — **본인 전공 우선**, 부족하면 타 전공(수강 가능 여부/제약사항 표시하며)
4. 학기별 권장 학점(기본 15~18, Curriculum 엔티티에 다른 값 있으면 그걸 우선)으로 로드맵 구성
5. **시간표 충돌 감지는 MVP 범위 밖** — 만들지 말 것

## 입력 (전부 받아야 추천 시작)

학과(복수전공·부전공 포함) · 현재 학년/학기 + 기이수 과목·학점(수기 입력, 성적표 업로드 연동은 범위 밖) · 관심분야(F3 태그 또는 자유입력) + **우선순위** · 졸업까지 남은 학기 수

## 출력 요구사항

- [ ] 각 추천 과목에 **버킷 표시**(전공필수/전공선택/관심분야) + **추천 사유 문장** (예시: "반도체 분야 연관도가 높고 전공선택 학점으로 인정됩니다")
- [ ] 사용자가 과목 추가/제외 → **나머지 재계산** (1회성 배치 추천이 아님, 플로우차트의 재계산 루프를 따름)
- [ ] Curriculum은 **입학년도별 버전** — 사용자 본인 입학년도 버전으로 계산
- [ ] **"참고용, 최종 확인은 학과 사무실"** 문구 — 빠지면 미완성

## Edge case

- 복수전공/부전공: 2개 이상 학과 요건 동시 반영 (하나만 골라 계산하지 말 것)
- 졸업 임박 고학년: 추천 여지 적음 → 적절한 안내 문구
- 관심분야 과목이 전공/수강가능 범위 내 부족 → 계절학기·교양까지 탐색 확장

## 아키텍처 메모 (PRD 10.3/10.4)

학점/선수과목 계산은 **결정론적 로직**(Route Handler 내부) — LLM에 산수를 맡기지 말 것. 관심분야 매칭/랭킹만 LLM API 위임. 연산이 길면 스트리밍 또는 비동기 생성 후 폴링(Vercel 서버리스 실행시간 제약).

깊은 구현(추천 엔진, 여러 파일)은 `curriculum-recommender` 에이전트에 위임하세요.
